# Contributing

Read [the development guide](development.md), root `AGENTS.md` and `SKILL.md`.
Project Tracker is specification-led: change the owning Component, Flavor or documentation,
then regenerate through the supported Literate AI lifecycle. Do not hand-edit generated
application source, source-cache entries or framework receipts.

Record the problem and acceptance gates in [active work](../roadmap/active-work.md).
Use synthetic fixtures for writes and protect private data in diagnostics. Run relevant
native and independent checks against the exact final export. Document any remaining
limits without describing an unfinished candidate as accepted.

Submit a focused PR explaining the problem, resulting behavior and verification. Keep
user documentation and `CHANGELOG.md` current. Inspect actual remote checks and follow
the repository landing workflow; an open PR or successful push alone is not merge proof.
